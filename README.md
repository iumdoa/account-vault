# Account Vault：本地账号密码管理器开发说明

本文是后续开发的需求、技术约定、执行顺序和验收依据。项目暂定名 Account Vault，目录为 `~/account-vault`。主要开发语言为 Dart，界面框架为 Flutter；先完成 Linux 版，再复用核心逻辑开发 Android 版。

当前状态：**仅完成开发文档，尚未创建 Flutter 工程或实现任何功能。** 文档中的命令是后续操作指南，不代表已经执行；代码片段是局部指导，不是完整实现。

编写日期：2026-09-18。依赖版本和平台 API 会变化，实施时应检查官方文档、锁定验证过的版本，并记录实际环境。

## 1. 目标与范围

### 1.1 解决什么问题

用户有较多网络设备、网站和应用账号，密码经常是随机字符串。现在需要翻文档查找，希望在 Linux 上通过快捷键打开面板，输入名称、IP、网址片段或备注，快速找到账号并复制。

典型流程：首次启动设置主密码 → 后续每次进程启动输入一次主密码 → 面板隐藏后程序继续运行 → 快捷键呼出 → 搜索 → 复制账号或密码 → 隐藏面板 → 下次直接使用。

### 1.2 已确认的需求

- 通用账号管理，不把记录限定为网络设备。
- Linux 优先，后续需要 Android，因此数据格式和核心业务必须可复用。
- 数据保存在本机，加密落盘，不需要服务器。
- 每次程序启动解锁一次；运行期间不自动锁定，包括隐藏窗口、系统锁屏和恢复之后。
- 支持快捷键呼出、搜索、账号与密码分别复制。
- 支持新增、编辑、删除，以及账号库的导出备份和恢复。
- 界面默认中文，适合个人日常使用，优先保证操作直接和数据可靠。

“不自动锁定”不等于把解密密钥保存到硬盘。退出进程后会话结束，下次启动仍需要主密码。忘记主密码无法恢复账号库，也不要实现所谓万能恢复密码。

### 1.3 第一版必须做

1. 创建、解锁本地账号库。
2. 通用账号记录增删改查、分组与标签。
3. 快捷面板和完整管理页面。
4. 搜索与鼠标/键盘复制。
5. niri/Wayland 环境中的快捷键呼出、单实例和后台驻留。
6. 加密备份导出、备份校验、整库恢复。
7. 明确的保存结果、失败处理、上一份有效文件恢复入口。
8. 可安装运行的 Linux release 产物和使用说明。

### 1.4 后续可做，不阻塞第一版

- CSV 批量导入、明确警告后的 CSV 明文导出。
- 修改主密码、密码生成器、收藏、可选剪贴板清理。
- 托盘图标、开机启动、更多 Linux 桌面环境适配。
- Android 界面和加密备份互通。
- 多设备自动同步、浏览器插件、Android 自动填充、TOTP。

暂不做多人权限、云端服务、附件、密码历史、富文本备注。不要把“未来可能需要”变成第一版的前置工程。

## 3. 用户界面与操作约定

### 3.1 启动和退出

- 没有账号库：显示“创建账号库”，主密码输入两次，成功写入后进入面板。
- 有账号库：显示解锁页面，输入主密码；错误不能创建空库覆盖原文件。
- 解锁中显示进度并禁止重复提交。成功后清除密码输入控件内容，不长期保存主密码字符串。
- `Esc` 在普通面板中隐藏窗口；在弹窗/编辑表单中先关闭弹窗或处理未保存修改，不能直接丢弃输入。
- 点击窗口关闭按钮默认隐藏；“退出程序”显式结束进程，等待正在提交的保存完成。
- 未实现可靠唤回机制前，不启用“关闭即隐藏”，否则可能把程序变成无法找回的后台进程。

### 3.2 快捷面板

初始宽度约 680、高度约 460 逻辑像素，可按显示缩放调整。上方搜索框，中间结果列表，下方简短操作提示和“管理”入口。密码默认不在结果列表显示。

每条结果展示标题、账号、地址、分组，以及“复制账号”“复制密码”两个按钮。同名账号必须能通过地址和用户名区分。

| 操作 | 初版约定 |
| --- | --- |
| 全局呼出 | 建议 `Super+Alt+P`，实际先检查冲突 |
| 面板打开后 | 自动聚焦搜索框 |
| 上下方向键 | 改变当前选中项 |
| Enter | 在结果导航场景复制选中项密码 |
| Ctrl+Enter | 在结果导航场景复制选中项账号 |
| Esc | 关闭当前弹层，或隐藏普通面板 |
| 点击复制按钮 | 写入系统剪贴板，并显示“已复制密码/账号” |

复制密码成功后默认隐藏快捷面板；复制账号后保持面板，方便继续复制密码。提示不能显示密码明文。编辑表单中的 Enter 遵循表单行为，不触发搜索结果复制。

中文输入法正在组合文字时，Enter 先用于确认候选字，不能误复制。空结果、没有选中项、账号为空时，相关复制操作不可执行。

### 3.3 完整管理页面

第一版在同一个窗口内切换“快捷面板/管理页面”，不做多个独立 Flutter 窗口。管理页面提供列表、分组筛选、编辑表单、备份与恢复入口和退出按钮。

保存成功后才关闭编辑表单；保存失败保留输入并允许重试。删除需要显示具体记录的确认对话框。显示密码是临时操作，切换记录、隐藏窗口或离开页面后恢复隐藏，但不锁定账号库。

## 4. 数据模型和搜索规则

### 4.1 一条记录对应一组凭据

同一设备有管理员和只读账号时，保存两条记录，使用相同地址、不同标题或用户名。第一版不引入“设备下挂多账号”的额外层级，网站和应用也用同一模型。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id | String | 随机 UUID，创建后不变 |
| title | String | 必填，例如“核心交换机 / 管理员” |
| address | String | 可空；网址、IP、主机名、应用标识，初版按原文保存 |
| username | String | 可空，支持只有密码的记录 |
| password | String | 可空，但 username/password 不得同时为空 |
| group | String | 可空，例如工作、个人、网络设备 |
| tags | List<String> | 去重后的标签 |
| notes | String | 纯文本，可多行 |
| createdAt | String | UTC ISO 8601 时间 |
| updatedAt | String | UTC ISO 8601 时间 |

账号和密码必须精确保留，不做 trim、Unicode 归一化或大小写转换。标题可以去除首尾空白，标签可以整理；这些规则必须集中实现，不能由不同页面自行决定。

长度采用明确上限：标题 256 字符、地址/账号/密码各 4096 字符、备注 64 Ki 字符、标签最多 32 个且每个 64 字符。超限给出字段错误，绝不静默截断密码。初版文件最大 32 MiB，最多 10000 条记录；导入前检查，后续需要放宽时更新格式约束和测试。

### 4.2 搜索

- 搜索 title、address、username、group、tags、notes，不搜索 password。
- 英文大小写不敏感，中文子串匹配；IP 和域名允许片段匹配。
- 查询去除首尾空白，按空白分词；所有词都命中任一可搜索字段才入选。
- 标题/地址完全匹配优先，其次前缀匹配、普通包含；相同分数按更新时间倒序、id 稳定排序。
- 空查询显示所有记录，采用稳定排序。切换查询后重置选中项，避免复制之前已选记录。
- 初版不做拼音、错别字纠正、全文数据库；将搜索逻辑做成纯函数，后续可扩展。

目标：1000 条合成记录下，release 版本输入后通常 100 ms 内更新结果。可使用短防抖，但不要让用户输入明显迟滞。这是待实测目标，不是已获得的性能数据。

## 6. 关键环节一：加密与账号库格式

这是第一版的必要基础，不能等界面全部做完才补。

### 6.1 加密边界

整个记录集合加密，包括标题、地址、账号、标签、备注和时间。不建立明文搜索索引。搜索只处理解锁后的内存数据。

允许明文保存不敏感的界面配置，例如窗口大小；不得保存主密码、派生密钥、最近搜索词、账号名称或最近复制的内容。开发日志、崩溃日志和测试报告不得包含真实凭据。

该设计保护静态数据文件；用户已明确选择运行期间保持解锁，不能宣称它能防御同用户恶意进程、内存读取或系统剪贴板历史。

### 6.2 固定第一版密码学参数

- 主密码编码：原始字符串 UTF-8，不 trim、不归一化。
- KDF：Argon2id，版本 0x13，32 字节输出。
- 初始参数方案：memoryKiB = 65536、iterations = 3、parallelism = 1。
- 新建库使用安全随机生成的 16 字节 salt；正常保存沿用该库 salt 和会话密钥。
- AES-256-GCM：32 字节密钥，12 字节 nonce，16 字节认证标签。
- 每次加密保存都生成新的安全随机 nonce，绝不由时间戳生成或复用旧 nonce。
- 修改主密码时生成新 salt、派生新密钥、生成新 nonce，再重新加密。

这些是本项目初始参数设计，不是性能结论。阶段 2 应测量目标 Linux 机器的解锁耗时和内存占用；Android 阶段也测量真机。KDF 放到工作 isolate，不能阻塞 UI；异步函数本身不保证重计算离开 UI isolate。若耗时不合适，先记录测量并调整方案，不暗中换成普通 SHA-256 或降低强度。

库中的 `memory` 参数单位是 KiB 大小的块，不能误把字节数传入。[Argon2id API](https://pub.dev/documentation/cryptography/latest/cryptography/Argon2id-class.html)

### 6.3 外层封装与内部数据

建议扩展名 `.avlt`。外层采用 UTF-8 JSON，包含四个字段：`header`、`nonce`、`ciphertext`、`tag`，值均为标准 Base64 字符串。

`header` 是头部 JSON 的原始 UTF-8 字节经 Base64 编码后的结果。其内部含：magic=`ACCOUNT_VAULT`、formatVersion=1、cipher=`AES-256-GCM`、kdf 名称/版本/参数、salt。头部原始字节直接作为 AES-GCM 的 AAD 认证。

**解密时必须使用文件里保存的原始 header 字节作为 AAD，不得解析后重新 jsonEncode。** 这样避免不同平台的 JSON 字段顺序或空白差异导致认证失败。外层字段名重复、未知必需结构、错误字段类型应拒绝；不要让宽松 JSON 解析掩盖格式歧义。

解密后的负载含 `schemaVersion=1`、`vaultId`、`revision`、`entries`。revision 是非负递增整数，用于保存顺序和诊断，不表示已经实现多设备冲突处理。

读取顺序：文件大小限制 → 外层结构/Base64 校验 → header 字节大小限制（例如 4 KiB）→ 头部识别/参数白名单 → KDF → GCM 认证解密 → 内部 schema/记录校验。不能先对任意外部参数分配大量内存再检查。

第一版只接受已定义的 KDF 参数配置，未知组合报“当前版本不支持该加密参数”，不擅自用默认值替换。将来加入更多配置时，显式列出可接受范围和资源上限。未知 formatVersion/schemaVersion 报“需要更新程序”，不能尝试按旧版读取后写回。

### 6.4 少量实现指导

下面仅展示派生与认证加密的调用关系。`salt` 需由安全随机源生成，`headerBytes` 必须包含与当前加密一致的算法和 KDF 信息；输入校验、工作 isolate、文件操作和异常映射不在片段内。

```dart
import 'dart:convert';
import 'package:cryptography/cryptography.dart';

Future<SecretKey> deriveVaultKey(String password, List<int> salt) {
  return Argon2id(
    memory: 65536,
    iterations: 3,
    parallelism: 1,
    hashLength: 32,
  ).deriveKey(secretKey: SecretKey(utf8.encode(password)), nonce: salt);
}

Future<SecretBox> sealVault(
  List<int> payloadBytes,
  SecretKey sessionKey,
  List<int> headerBytes,
) {
  final cipher = AesGcm.with256bits();
  return cipher.encrypt(
    payloadBytes,
    secretKey: sessionKey,
    nonce: cipher.newNonce(), // 每次保存重新生成
    aad: headerBytes,
  );
}

// 解密：重建 SecretBox(ciphertext, nonce: nonce, mac: Mac(tag))，
// 调用 AesGcm.with256bits().decrypt(box, secretKey: key, aad: headerBytes)。
// 认证失败时不能继续解析，更不能用空数据覆盖文件。
```

API 应以锁定依赖版本为准。[AES-GCM API](https://pub.dev/documentation/cryptography/latest/cryptography/AesGcm-class.html)

### 6.5 必须通过的加密测试

- 中文、emoji、换行、空字段和含前后空格的密码加解密后完全一致。
- 错误主密码认证失败，不改动原文件。
- 篡改 header、nonce、ciphertext 或 tag 后拒绝读取。
- 相同记录与密钥加密两次得到不同 nonce/密文，均可正确解密。
- 截断、超大文件、非法 Base64、未知版本、夸张 KDF 参数有明确错误。
- 使用公开算法测试向量或独立实现校验至少一组结果，不能只有本程序自身的往返测试。
- 建立仅含虚构凭据的固定 `.avlt` 测试样本，记录测试主密码，用于后续 Android 互通。固定 nonce/salt 只允许用于测试向量。

阶段 2 通过后，补齐 `docs/format-v1.md` 的字段、长度、编码、错误码、完整测试向量，再让 UI 依赖这个格式。

## 7. 关键环节二：可靠保存与异常恢复

### 7.1 数据路径

Linux 遵守 XDG 数据目录，由路径适配器给出稳定位置，例如 `$XDG_DATA_HOME/account-vault/`，未设置时使用 `~/.local/share/account-vault/`。Android 使用应用私有数据目录。不要依赖当前工作目录，也不要把真实库放在源码目录。

目录建议权限 0700，账号库、临时文件与本地回退文件 0600。文件只含密文。权限应在创建阶段设置，必要时使用小型原生适配；不能先写明文再 chmod。程序不跟随意外的符号链接覆盖其他文件。

文件约定：`vault.avlt` 为主库；`vault.previous.avlt` 为上一份有效版本；临时文件使用唯一名称。锁文件独立存在，不锁住会被 rename 替换的主库 inode。

### 7.2 保存事务

所有修改通过同一个串行队列；新增、删除、恢复、退出前等待都遵守同一规则。不能让两个异步保存互相覆盖。

推荐采用“先持久化候选快照，成功后发布内存状态”：

1. 基于最近已提交状态生成下一份候选快照，校验并递增 revision。
2. 加密候选快照，得到完整新文件字节。
3. 在主库同一目录创建唯一临时文件，写入全部密文字节，flush 并关闭。
4. 用当前会话密钥读回验证临时文件可解密，确认记录结构有效。
5. 如果主库存在，把当前已验证的主库复制到另一个临时文件，flush 后原子替换 `vault.previous.avlt`。
6. 原子 rename 新临时文件覆盖主库。**不要先删除主库。**
7. 尽可能同步目录元数据；成功后发布新内存状态，再向 UI 返回保存成功。

初次创建同样使用临时文件提交，必须先持有写锁且确认不存在已有库。损坏文件不是“没有账号库”。

同目录 rename 解决替换过程的原子性，文件 flush 与目录 fsync 关系到突然断电时的持久性。Dart 的高层文件 API 不一定完整提供目录同步，需要在 Linux 实测并视情况做原生适配。不能把“用了 rename”描述为已经证明任意断电都不会丢失数据。

若 rename 前失败，旧主库保持不变；若 rename 成功但目录同步失败，属于提交状态不确定：重新读取主库判断 revision，提示用户持久性风险，不能直接当作未提交重放新增操作。

### 7.3 启动恢复规则

| 情况 | 行为 |
| --- | --- |
| 主库存在且有效 | 正常解锁；孤立临时文件不自动替代主库 |
| 主库存在但解锁失败 | 提示“密码错误或文件损坏”，允许重试或选择备份 |
| 主库缺失但 previous/临时文件存在 | 进入恢复页面，不能直接创建空库 |
| 主库损坏、previous 可解锁 | 展示回退文件信息，确认后恢复，保留损坏原件 |
| 所有文件不可读 | 保留文件，提供错误与导入备份入口 |

认证失败不能可靠区分错误密码和某些损坏，所以不要一失败就自动回滚。临时文件只在明确处理后清理；恢复前不删除唯一可能的数据副本。

### 7.4 必须验证的失败场景

使用故障注入，在写临时文件、回退文件替换、主库替换前后分别模拟异常。验证至少存在一个可解密的完整版本，绝不出现被当成正常空库的损坏文件。

还要测试：目录只读、空间不足、连续快速提交、保存中退出、两个进程同时启动。普通进程崩溃测试和真实断电保证要区分记录。

## 8. 关键环节三：niri / Wayland 快捷唤起与单实例

### 8.1 先做可行性验证

这个环节在完整 UI 之前验证。Wayland 的焦点和窗口定位由合成器约束，单独调用 `show()`/`focus()` 不代表一定能从别的工作区切过来。

第一版约定命令：`account-vault --show`。无实例时启动并显示解锁页；已有实例时只发送唤起请求，不能再创建一个可写账号库的会话。重复请求只显示窗口，不反复切换隐藏状态。

优先研究 Flutter Linux runner 的 GTK/GApplication 单实例激活机制，检查生成代码是否启用了非唯一实例模式，处理参数转发、应用 ID 与桌面激活信息。若采用本地 IPC，限于用户会话 D-Bus 或 `$XDG_RUNTIME_DIR` 下受限 Unix socket，不开启 HTTP 服务。

单实例不能靠“先检查进程名，再启动”的竞态方案。必须由系统原子名称占用或独立 OS 文件锁保证只有一个写入者；第二实例只发控制请求后退出。启动进行中也要能排队接受显示请求。

IPC 只提供 `show` 等控制操作，不提供获取密码、导出账号或携带主密码的接口。不得把密码写入命令行参数。

### 8.2 niri 绑定示例

程序安装后，将一条绑定合并进用户已有的 `binds` 块，不覆盖整份配置。以下路径是计划安装位置，当前还不存在该启动器。

```kdl
binds {
    Super+Alt+P repeat=false {
        spawn "/home/iumdoa/.local/bin/account-vault" "--show";
    }
}
```

niri 的 `spawn` 参数应分别传递，不把整条带空格的命令放在一个参数中。修改前备份配置、检查冲突，并用本机版本支持的配置校验命令验证。[niri 快捷键文档](https://niri-wm.github.io/niri/Configuration%3A-Key-Bindings.html)

可通过 niri 窗口规则使面板浮动；先用 `niri msg windows` 确认真实 app-id，再写规则。管理页面初版也可以使用同一个可调整大小的浮动窗口，不必为了不同布局引入多窗口引擎。[niri 窗口规则](https://niri-wm.github.io/niri/Configuration%3A-Window-Rules.html)

若 GTK 激活无法稳定聚焦，应在 Linux 适配层补充经过验证的 niri IPC 聚焦流程：先请求现有进程显示，等待窗口实际映射，再定位对应 app-id/窗口 ID 并聚焦。使用参数数组调用命令，检查错误和超时，不能拼接用户记录为 shell 命令。不要靠固定 sleep 假装解决竞态。

跨桌面后续可研究 GlobalShortcuts portal，但它的存在不等于当前桌面后端已经支持。首版不以所有 Wayland 桌面通用为目标。[Portal 接口](https://github.com/flatpak/xdg-desktop-portal/blob/main/data/org.freedesktop.portal.GlobalShortcuts.xml)

### 8.3 唤起验收

- 从终端、浏览器、其他工作区触发，窗口可见且搜索框获得焦点。
- 连续触发 20 次仍只有一个账号库写入实例。
- 隐藏/唤起重复 20 次，解锁会话保持，不重复问主密码。
- 冷启动显示解锁页，解锁后进入搜索；锁屏解锁后保持原会话。
- 显式退出后再触发，需要重新输入主密码。
- 从不同工作目录执行启动器都正常，不依赖终端环境中的临时 PATH。
- 没有托盘服务时仍能通过快捷键找到程序并显式退出。

## 9. 关键环节四：备份与恢复

### 9.1 加密备份

第一版默认只导出加密 `.avlt`，使用导出时账号库的主密码解锁。流程：等待保存队列完成 → 获取已提交快照 → 校验源文件 → 导出到用户选定位置 → 确认写入完成 → 显示结果。

Linux 下可直接复制已验证的完整加密文件，复制不等于使用旧 nonce 重新加密，因此不会引入新的 nonce 复用加密操作。导出目标不能是主库、previous 或其等价/符号链接路径；不要覆盖工作账号库。

文件名可用 `account-vault-backup-20260918-153000.avlt`，不含记录标题或账号名称。相同目标文件已存在时需要处理覆盖确认。取消文件选择不报保存失败，也不产生空文件。

导出成功只意味着文件写出；应另提供“验证备份”或通过恢复预览完成解密验证。至少一次在独立测试数据目录里恢复成功，才算验证备份可用。

`vault.previous.avlt` 只是本机回退版本，不等于独立备份。用户可把加密备份复制到自己的其他存储位置。

### 9.2 整库恢复

首版只实现“整库替换”，不做合并，避免重复记录和冲突规则膨胀。

1. 选择备份文件，检查大小、封装与版本。
2. 输入该备份的主密码，独立解密并完整校验。
3. 展示记录数量和替换提示，不暴露密码。
4. 现有库已解锁时，先生成一份带时间戳的独立恢复前加密备份，展示路径。
5. 用户确认后，走同一保存队列和原子提交机制，提交恢复结果。
6. 恢复成功后切换会话状态与界面，清除旧查询和选择。

恢复语义必须固定：**整库恢复后采用导入备份的主密码和加密参数**，下一次启动使用备份密码。界面在确认前明确说明，不能让用户误以为仍使用旧密码。

当前主库打不开时也应能导入恢复：先把现有原始文件保留为独立救援副本，不宣称其有效，再替换。没有当前库时可直接初始化为导入的库。任何失败都保留旧库和原始导入文件。

恢复必须与所有写操作串行；预览期间数据若发生变化，需要在实际提交前重新确认要替换的状态，不能基于过期确认静默覆盖。

### 9.3 CSV 后续约定

建议阶段 7 再做。字段映射为 title,address,username,password,group,tags,notes；使用成熟 CSV 解析器，处理逗号、双引号、换行、UTF-8 BOM，不能直接按逗号 split。

导入先预览、显示错误行、确认后一次事务提交；默认给每条导入记录生成新 id，不按标题静默覆盖。重复导入需提示或提供显式跳过规则。密码中的空格和换行原样保留。

明文导出必须由用户主动选择并提示文件包含密码。若未来增加“电子表格安全导出”，要与可无损重新导入的原始导出区分，不能为了防公式解释而静默修改密码值。

## 10. 剪贴板与密码显示

第一版使用系统剪贴板接口，分别复制单个字段。await 写入成功后再反馈；平台报错时留在界面并给出失败提示。密码为空时禁用复制，不用空串覆盖用户剪贴板。

复制行为必须用虚构密码在浏览器输入框和终端编辑器等不同应用间测试。niri/Wayland 下尤其验证面板隐藏后内容仍可粘贴。

不把自动清理剪贴板列为 MVP 必须项。若后续添加：延时清理前先确认剪贴板仍是本程序刚复制的内容，用户复制了其他内容则不清理；计时器必须处理连续复制。系统剪贴板历史不受本程序完全控制，不能声称已从所有历史中删除。

## 11. 分阶段开发流程与完成条件

严格按顺序推进。每阶段交付一个可验证结果；关键阶段失败时先解决原因，不通过删掉验收条件来宣布完成。

### 阶段 0：环境、工程和桌面可行性

任务：检查环境 → 安装/选择 SDK → 创建 `app/` → 跑通 Linux 空应用 → 确定 app-id → 验证隐藏/显示/聚焦 → 验证 `--show` 激活已有实例 → 写最小 niri 绑定示例。

暂用假数据，不访问真实账号。记录 Wayland 原生运行与插件表现，完成第 8 节的核心唤起试验。如果窗口控制不可靠，在这个阶段调整平台适配，不要先写几千行业务 UI。

交付：可运行空壳、最小唤起链路、`docs/environment.md`、`docs/progress.md`。

完成标准：niri 下快捷键可打开并聚焦已有窗口；重复触发不产生第二个可写实例；Linux release 可构建。此时只是技术可行，尚不能存真实密码。

### 阶段 1：模型、搜索与假数据面板

任务：实现记录模型/校验、纯搜索函数、中文界面、结果导航、编辑表单与假数据仓库。准备覆盖设备、网站、应用的 20 条虚构记录。

交付：可演示的内存版本；搜索和字段校验测试。

完成标准：名称/IP/域名/备注/多个词都按规则搜索；中文输入法 Enter 不误复制；账号密码精确保留；关闭程序会丢假数据这一限制在开发说明中标明。

### 阶段 2：加密格式和可靠文件仓库

任务：冻结封装格式 → 实现 KDF/AEAD → 基准测量 → 实现工作 isolate → 路径和权限 → 串行保存和原子替换 → 故障注入 → 回退恢复。

交付：`docs/format-v1.md`、虚构测试向量、加密仓库、关键自动测试、性能记录。

完成标准：第 6 节测试通过，第 7 节失败场景有证据；原文件不会被错误密码或损坏输入覆盖。只做到加解密往返不算完成本阶段。

### 阶段 3：真实存储闭环

任务：将假数据仓库替换为加密仓库，接上创建/解锁、增删改、隐藏驻留、显式退出和会话状态。完成账号与密码复制。

交付：启动输入主密码 → 编辑 → 保存 → 退出 → 重启解锁后数据仍存在的完整流程。

完成标准：保存失败不假报成功、不丢表单；密码输入不被日志记录；隐藏唤起不重新解锁；真正退出后重新解锁。此时仍以虚构凭据验收。

### 阶段 4：加密备份与整库恢复

任务：文件选择、加密导出、备份验证、恢复预览、恢复前独立备份、事务替换、失败恢复。

交付：备份与恢复界面、测试和清楚的主密码语义提示。

完成标准：在独立数据目录恢复出完全一致的记录；错误密码/损坏备份不改变现有库；恢复成功后重启能用备份密码解锁；取消操作无副作用。

### 阶段 5：Linux 发布与实际使用验收

任务：构建 release，制作启动器与 `.desktop` 文件，安装到用户目录，验证完整 bundle、niri 绑定和正式数据路径，完成第 12 节矩阵。

交付：可运行 Linux 产物、安装/升级/卸载说明、手工验收报告、备份恢复演练记录。

完成标准：**第 12 节所有 MVP 必须项通过，才算完成用户当前 Linux 目标。** 不需要等 Android、CSV 或云同步完成。通过后再由用户把真实凭据迁入使用。

### 阶段 6：Android 基础版

任务：按官方指南配置 Android SDK/JDK → 先构建现有共享核心 → 实机验证加密样本 → 手机列表与编辑界面 → 系统文件选择/导出 → 复制 → 双向备份互通。

完成标准：Linux 产生的备份能在 Android 解锁、编辑、重新导出，Linux 能读取；反向亦然。记录字段和密码逐字节一致。Android 独立生命周期与导出权限通过实机验证。

### 阶段 7：按实际需要增加便利功能

CSV 导入优先于复杂主题；再考虑生成密码、修改主密码、托盘和开机启动。同步与自动填充单独设计，不能塞进一次小改动。

## 14. Android 复用边界

共享内容：模型、校验、搜索、加密封装、备份解析、保存用例、错误映射和大部分界面组件。

单独适配：应用目录、文件选择与导出、系统剪贴板、生命周期、窗口布局。Linux 托盘/窗口/快捷键代码只能在 Linux 初始化，不能在 Android 启动时调用桌面插件。

手机后台进程可能被系统杀死；进程仍在时继续保持解锁，进程被杀后再启动要求主密码，这是“启动时解锁”的自然结果，不是额外自动锁定功能。

Android 的用户选中文件可能是 content URI，不能当普通路径传给 `File`。先验证选定文件插件的能力；若保存位置 API 不支持 Android，使用系统 Storage Access Framework 的文档创建/读取接口或合适插件，以字节流导入导出。[file_selector 能力说明](https://pub.dev/packages/file_selector)

内部保存仍在应用私有目录，外部导出失败不能影响主库。Android 测试不只依赖模拟器；至少一台真机验证解锁耗时、中文输入、文件提供者与剪贴板。

两端第一阶段通过备份文件交换数据，不自动监视共享目录，不把网盘同步文件直接作为实时工作库。同步需要独立的冲突、删除和版本策略。

Android 开发环境以[官方配置文档](https://docs.flutter.dev/platform-integration/android/setup)为准，记录实际 Android SDK、JDK、Gradle 和最低系统版本，避免凭记忆随意拼接版本组合。

## 15. 后续便利功能中的高风险点

### 15.1 修改主密码

后续实现时必须事务化：确认新密码两次 → 新 salt/KDF/key → 用当前记录生成新密文 → 验证 → 原子提交 → 最后替换内存会话密钥。中途失败仍能用旧密码打开原库。

旧独立备份继续使用旧主密码，不能声称修改主密码会自动更新已导出文件。本地 previous 也可能仍由旧密码加密，恢复页面需要允许输入对应密码。

### 15.2 自动启动

只在核心流程稳定后添加。启动系统后程序仍需一次主密码；不得通过把主密码放入自启动命令来实现“免输入”。不同时注册多个自启动入口造成重复启动。

## 16. 交给后续开发模型的工作方式

每轮先阅读本文及 `docs/progress.md`，确定当前阶段和未完成验收项。一次完成一个可运行的小阶段，避免一次生成整套未经验证的程序。

每阶段结束更新进度：实现内容、实际运行命令、测试结果、已知问题、下一步。发现平台 API 不适用时，记录证据与替代方案，不编造函数、不把异常全部吞掉。

必须遵守：

- 不自行加入自动锁定，不修改已确认的“进程启动解锁一次”语义。
- 不把密码持久化到 SharedPreferences、普通 JSON、日志或源码。
- 不使用自制加密、固定密钥、固定 nonce 或无认证的简单加密包装。
- 不因错误密码或解析异常创建空库覆盖已有数据。
- 不把所有逻辑塞入 `main.dart`，也不为简单应用设计庞大框架。
- 不在业务代码散布 niri 命令；平台代码集中封装。
- 不用真实账号做测试，不要求把真实密码发给模型。
- 涉及格式变更先更新格式文档和兼容测试，不能静默改变文件意义。
- 遇到密码学互通、原子保存、Wayland 焦点等难点，保留最小复现、脱敏日志和已试方案，再交给用户决定是否寻求进一步帮助。
